# Technical Overview

The project is built to keep almost all heavy work on the GPU.

### CUDA

CUDA handles the simulation core.

- The simulation state is stored in GPU-side buffers and updated every frame. These buffers are shared between OpenGL and CUDA.
- Convolution is performed with cuFFT rather than direct spatial convolution, which keeps large-kernel Lenia updates practical on a 1024x1024 field
- A custom CUDA kernel applies the post-FFT update step, combines the inverse transform with the Lenia growth function, and writes the next state back into the simulation field
- The code also computes motion-related statistics such as mass and toroidal center of mass so the application can expose live control and diagnostics

The important design choice here is frequency-domain evolution: instead of looping over every cell and every kernel sample in the spatial domain, the code transforms the field once, multiplies by the precomputed organism kernel spectrum, and transforms back.

### OpenGL

OpenGL is used as both presentation layer and GPU data bridge.

- The field is backed by shader storage buffer objects (SSBOs) and rendered directly through the graphics pipeline
- GLFW, GLAD, and ImGui provide the graphical display, OpenGL context, input handling, and overlay UI
- OpenGL textures are also used to preview the organism mask, padded kernel, and FFT magnitude in the interface
- CUDA/OpenGL interop lets the renderer and simulation share buffers without round-tripping field data through the CPU every frame. Seeding and clearing update the existing field buffer allocation rather than replacing it, preserving the registered CUDA buffer storage

The simulation writes GPU memory that the renderer can immediately visualize, so rendering the world is mostly a matter of drawing a fullscreen quad and overlaying UI. Color palettes are defined in [colors.hpp](../source/lenia/colors.hpp). The desktop Color Palette selector offers Magma, Greyscale, Ocean (blue to turquoise), Aurora (purple through cyan to green), Ember (red through orange to cream), and Ice (dark blue to white). Each new palette has six RGB stops, smoothly interpolated by cell density. Magma remains the desktop and wrapping-stream default. In circular streams, each organism independently receives a random palette from Magma, Ocean, Aurora, Ember, and Ice, excluding Greyscale. Its palette stays fixed during its lifetime and is selected again on rebirth; palettes may repeat across organisms. The five palettes are uploaded once and the renderer binds the selected palette buffer for each organism.

The [FastAPI application](../server/app.py) registers the [HTTP and WebSocket routes](../server/routes.py). [Request models](../server/models.py) validate configurations using the [animal catalog](../server/catalog.py); [worker management](../server/worker.py) handles the subprocess lifecycle and frame requests, and [frame encoding](../server/frames.py) handles JPEG conversion. The [circular arena coordinator](../server/arena.py) handles frame pacing and replacement births. The [native arena](../source/lenia/stream_arena.cpp) evolves organisms with separate species kernels and coupled density fields in one CUDA/OpenGL process and performs rotation, translation, clipping, and composition on the GPU using the [arena shader](../shaders/arena.frag). WebSocket lifecycle logs include the client address on opening and closure, with a closure reason for disconnects, stop requests, busy rejections, errors, and cancellation.

The server controls a separate C++/CUDA worker over stdin/stdout. Circular arenas use `--stream-arena`, with one independent simulation field per organism in a single OpenGL context; wrapping fields use `--stream`. Both report `READY` after a numeric configuration and emit one fixed-size RGB image per `n` command. Arena frames prefix the completed RGB image with one native-endian float32 CUDA mass per organism. The native arena measures visible bounds on the GPU, reading back only four integers per organism to fit sprites and set hidden turning radii. The rendering shader samples each CUDA-backed field directly, rotates it from its natural heading to its velocity, and composes it into the hidden window's back buffer. Only the completed image is copied from GPU to CPU; interaction diagnostics add up to one hundred float32 contact totals. Python flips it and encodes JPEG off the event loop; it no longer crops, rotates, or composes individual images. Replacement commands (`r`, slot index, organism configuration, random angle) reseed a slot in the same native process and acknowledge `READY`. Frame and replacement I/O are serialized so their responses cannot interleave. Reseeding releases the old field’s CUDA registrations and organism textures before replacing them. Seed initialization waits for pending OpenGL uploads before writing the complex CUDA field, preventing delayed uploads from overwriting newly initialized density.

Clients discover zero-based organism type IDs through `GET /organisms` and connect to `/ws`. Their first text message is a JSON configuration:

```json
{
  "action": "start",
  "size": 512,
  "fps": 20,
  "dt": 0.1,
  "organisms": [
    {"type": 0, "scale": 1, "x": 128, "y": 128},
    {"type": 0, "scale": 1, "x": 320, "y": 320}
  ]
}
```

`pixel_size` sets global animation pixelation (integer 1–16, default 1). The completed frame is downsampled with box filtering and enlarged with nearest-neighbor sampling before JPEG encoding, keeping its output dimensions. Use 1 for full detail, 2 for subtle blocks, and 4 or 8 for stronger pixelation. Circular arenas apply this once after GPU composition; individual simulation fields retain full detail. `size` defines a square world and output resolution (256–1024); `fps` caps delivery at 1–60 frames per second; `dt` is the simulation timestep, greater than zero and at most 0.2. The organism array contains 1–100 instances. Positions must be inside the world, scale is an integer from 1 to 10, and the organism kernel must fit the world. The default `boundary: "wrap"` evolves one shared field, so all instances share one type and scale. `boundary: "circle"` supports up to one hundred different types and scales, each with its own CUDA field in a shared native worker, with fluid effects disabled. Each isolated field uses the smallest suitable power-of-two size (at least 256 when the configured world allows it, at most the configured world size), allowing space for the seed and kernel without changing its pixel scale. Each organism’s timestep is capped at the smaller of the requested `dt` and its catalog timestep. GPU shaders handle organism bounds, rotation, and composition, and FPS pacing uses successive deadlines once per completed arena frame. The pygame client requests 60 FPS by default. Hold Space or C in the pygame client or browser viewer during a circular simulation to steer organisms toward the invisible edge at the server-configured `space_speed_multiplier` times their normal speed (default 2.0, finite and at least 1.0); release it to restore normal speed and steer toward the center. Hold V to steer toward the center with the same speed boost. Releasing all steering keys restores normal inward movement; when multiple keys are held, the most recently pressed key takes priority, and releasing it restores the remaining held key. The server receives `outward`, `inward`, and `inward_fast` commands, with separate native direction and boost state. Each organism selects its own random heading offset within about ±37 degrees every two animation seconds and gradually turns at up to 0.8 radians per animation second while preserving the current speed multiplier. Newborns also receive the current multiplier. Center-directed steering is the initial mode; hidden-boundary reflections still apply. Losing viewer focus releases the control. A previous local 100-organism sample delivered about 17.7 FPS at 1024×1024 despite requesting 60 FPS; delivery depends on the randomly selected species, GPU, JPEG encoding, network, and client. The native renderer fits the evolved organisms and clips their display to a circle with radius 90% of the arena radius within the square output. The background is black with no circle outline; circular clipping and movement boundaries remain active. Organisms travel into the hidden margin and reflect only after the entire rotated image is outside the visible circle. The hidden turning boundary accounts for each organism’s radius, so large organisms also disappear before rotating. Circle mode derives velocity inversely from configured organism size: `size_pixels = max(seed_width, seed_height) × scale`, and `base_velocity = 25 × smallest_size_pixels / size_pixels`, measured in display pixels per simulated second at the configured FPS. Each organism independently receives a uniformly random speed multiplier from 0.5 to 2.0 on initialization and rebirth, held constant throughout its lifetime and independent of its display multiplier. Its normal speed is `base_velocity × speed_multiplier`; holding Space additionally multiplies this by `space_speed_multiplier` (default 2.0). Releasing Space restores its individual normal speed. The smallest organism has base speed 25; doubling seed size halves base velocity relative to the same smallest seed size. Velocities are recalculated for the whole arena after every birth without changing headings. The `velocity` field remains accepted and validated (greater than zero, at most 25), but circle mode replaces it with the derived value. It applies explicit translation independently of natural Lenia evolution. Overlapping displayed bodies now interact through the [CUDA coupling kernel](../source/lenia/stream_interaction.cu): previous-frame transforms map each body into its neighbors’ fields, with bilinear sampling and GPU snapshots taken before any coupled updates to avoid slot-order bias. Contact only measures overlapping density and accumulates injury; it does not add density or apply constructive/destructive bands. Injured organisms gradually lose mass and disappear, without interference-driven expansion. Actual overlapping density accumulates persistent injury. Injured slots continue Lenia evolution at their normal timestep using health-normalized density, with growth increments scaled by health. CUDA uniformly multiplies density by the ratio of new health to previous health on each damage step. At first injury, a GPU envelope captures the occupied cells above the renderer’s 0.02 density threshold, without extending the silhouette. Subsequent updates clear cells outside this footprint and cap density inside it at current health. Internal evolution can change density within occupied cells, but previously invisible cells cannot become a surrounding square. Internal motion is constrained by this fixed silhouette. The envelope remains fixed until rebirth and is allocated only for injured slots. Natural evolution can cause small mass fluctuations during fading; zero health clears the field. Injured slots retain their last healthy natural heading, source center, bounds, and rendering scale, so fading does not rotate, recenter, or enlarge them. Arena velocity and boundary reflections continue normally. Isolated organisms do not accumulate injury. Death follows the decreasing simulation mass; reseeding resets injury and restores full health. Interactions use GPU-to-GPU field copies only for potentially overlapping bodies, cropped CUDA kernels, and a contact readback of one float per slot. Health decreases at `0.08 × accumulated stress + 0.30 × current contact` per animation second, twice the previous damage rate. Damage advances with requested frames at the configured FPS; pauses also pause damage. Velocity does not control the wrap-mode simulation. Large size differences can produce derived velocities below 20. Large evolving sprites are fitted to the arena. Initial positions outside the hidden movement boundary are moved inside on the first frame. Circle-mode seeds must be at most one-third of the world size. Arena rendering rotates each organism from its measured natural forward direction to its arena velocity, including after reflections. Natural heading uses raw toroidal center-of-mass displacement over 0.5 animation seconds, accepting only net movement above 0.1 simulation pixels and above 25% of total movement during that interval; this rejects internal back-and-forth pulsing. Heading changes are limited to 0.8 radians per animation second. Render centering follows the toroidal shortest path with a 0.12-second exponential response, and rendering fit uses a 0.3-second response instead of changing abruptly with each bounding box. Collision and clipping extents include the centering lag so the smoothed sprite remains covered. These filters affect composition only; the Lenia timestep and field evolution stay unchanged, and injury still freezes the last healthy render transform. A slot is considered dead after five consecutive frames with CUDA mass at or below 0.001. Its native slot is reseeded asynchronously with a uniformly selected compatible catalog type allowing repeats of living types, at scale 1 and a size-derived velocity. Selecting the type before its scale gives every eligible type equal probability. A birth may reuse the dead slot’s previous type or any other living slot’s type; a pool with no geometrically fitting type reports an error. The replacement starts fully outside the visible circle at a uniformly random boundary angle, takes a random heading within 45 degrees of inward, and enters naturally instead of aiming at the center. Detection uses simulation mass, so hidden turns do not trigger births. Death and birth events are logged, and pending births are cancelled before worker cleanup on disconnect. The inclusive `ORGANISM_RANGES` tuple in `server/catalog.py` controls types available for animation requests and births and defaults to `((0, 17),)`. Add more `(first, last)` intervals to extend selection; overlapping intervals are deduplicated. Every type within these intervals is eligible, with no square blacklist or kernel/growth-rule filter. Only geometric fit restricts birth selection; repeated types keep replacements available with 100 occupied slots. The legacy JSON `excluded_types` list is accepted for compatibility but ignored and defaults to empty. Each circular-arena organism receives a uniformly random display multiplier between 0.5 and 2.0 on initialization and rebirth, held constant throughout its lifetime. This multiplies the original rendering fit (native size capped at 64 pixels on the longest axis), allowing bodies up to 128 pixels while preserving aspect ratio. Bilinear density sampling smooths display enlargement without changing simulation scale or field resolution. Collision transforms, clipping bounds, and hidden turning radii use the resulting display size; injured organisms retain their last healthy fit while fading. The pygame preset creates 100 slots by cycling a shuffled list of fitting types in the configured intervals (18 types in `0–17` by default), without a type blacklist or rule filter. Types repeat with balanced counts, with scale 1 and initial positions distributed uniformly by area in a disk of radius 400 pixels around the center of the 1024-pixel arena. Initial bodies start inside the visible circle with fully random headings; newborns still enter from the hidden boundary margin. The population has 100 slots, but overlapping bodies, fading, and offscreen entries or turns can reduce the number visibly distinguishable at once. Interior spawns receive uniformly random headings over the full circle. Initial circle-mode positions at the boundary are moved fully outside the visible circle using the measured body radius before rendering; custom interior positions remain supported. Slots can be temporarily empty during reseeding; initialization is serialized with frame production and can briefly extend a frame. The first frame uses a downward fallback until a natural movement direction is available; stationary organisms retain their last heading. User-specified rotation is unsupported. Type names come from the existing animal catalog.

The server replies with JSON status/error messages. After `{"status":"started",...}`, send the text `next` to receive one binary JPEG message. Keep at most one next-frame request in flight. The [browser viewer](../server/viewer.html) requests after displaying the previous frame. The pygame client requests the next frame immediately before decoding/displaying the current one, overlapping server computation with client rendering. Pausing requests pauses simulation evolution; the FPS setting caps speed rather than guaranteeing a real-time simulation clock. Send `stop` or close the socket to end the simulation. Restarting opens a fresh connection. Idle connections expire after 60 seconds, including paused viewers; worker startup and frame reads time out after 30 seconds. The server cancels pending births, then kills and reaps the native worker on disconnect or failure.
