# Python Experiments

Before moving everything into CUDA, I used a CPU FFT prototype (since removed) to prototype the FFT pipeline and generate quick Matplotlib-based debug animations. That was substantially easier to inspect than debugging the same ideas inside CUDA kernels, and it helped validate padding, FFT multiplication, inverse transforms, and shift behavior before porting them to the GPU implementation. Below you can see an animation showing an instance of $\textit{Orbium Unicaudatus}$ evolving under the FFT-based update rule, and interacting with a wall obstacle. The top-right corner shows $|\hat{G}|$, the bottom left shows the shifted convolution result $G_{\mathrm{shift}}$, and the bottom-right corner shows just the growth function $H$ multiplied by $\Delta t$.

The server’s default preset now streams 50 larger copies through [the CUDA worker](../source/lenia/stream_hexapod.cu), with independent motion, sizes, palettes, and fluid fields, all updated and rendered on the GPU. In the CUDA gait, each arm independently randomizes its step threshold (150–250 pixels), swing duration (0.18–0.50 seconds), recovery delay, lateral reach, and extension margin after every stroke. Initial per-arm delays break synchronization while at least four feet remain planted. Each CUDA hexapod maintains a straight trajectory, reflecting its travel vector only at the hidden outer limit (`world radius + 8 + sprite diagonal radius`), after the entire sprite has left the visible circle. It does not continuously steer around or toward the center. Steering commands set a new inward or outward trajectory once; edge reflection then continues normally. CUDA body-density overlap accumulates injury: falling health contracts the head, torso, and arm segments, folds the arms toward the body, and slows propulsion and strokes while the body and trail fade to zero. The server replaces dead slots with new hexapods entering from outside the visible circle, resetting injury and fluid state and randomizing size and palette. The standalone CPU walker and its tests have been removed. Save the [CUDA GIF preview](../resources/hexapod/propulsion.gif) using `uv run python -m lenia.scripts.record_hexapod_cuda`; `--output` selects the destination, `--duration` accepts up to 30 seconds (default 30), and `--fps` accepts 5–60 (default 25). `--speed` controls playback movement speed (default 2, twice the original speed); speed divided by FPS must not exceed 0.2. Use `make video` to encode a 1080×1920 portrait MP4 at four times the original movement speed with FFmpeg. The recorder’s `--story` option centers the square render on a black portrait canvas without stretching or cropping the creature; `--output resources/hexapod/propulsion.mp4` selects MP4 encoding. The native `--stream-hexapod-preview` mode uses a fixed camera and the original reference palette, displaying the organism at its original preview scale divided by 1.5. It travels once from the top-left corner to the bottom-right and leaves the frame, without wrapping, turning, or arena clipping. Motion, density, fluid, and color rendering use the same CUDA kernels as the server; Python only receives frames and encodes the GIF. The preview renders 750 frames over 30 seconds at 1024×1024; GIF encoding can merge identical empty frames after the creature exits, with [sampled poses](../resources/hexapod/propulsion.png).

The earlier evolution experiment remains available as an [initial seed](../resources/hexapod/seed.png), [standalone catalog-format definition](../resources/hexapod/organism.csv), and [native runner](../src/lenia/scripts/hexapod_experiment.py), outside the active catalog and random births. Its limited [CPU parameter survey](../resources/hexapod/search-report.json) tested 54 broad and 96 narrower combinations using the existing polynomial Lenia rules without finding a stable six-arm swimmer. Native verification at `R = 13`, `mu = 0.15`, `sigma = 0.015`, scale 1, and `dt = 0.1` shows that the arms lose their structure within about 30 steps and the pattern subsequently spreads across the field; the [animation](../resources/hexapod/evolution.gif), [sampled frames](../resources/hexapod/evolution.png), and [mass measurements](../resources/hexapod/report.json) record that unsuccessful prototype. Run `uv run python -m lenia.scripts.hexapod_experiment` after building `build/lenia` in a CUDA/OpenGL desktop session to reproduce its 600 native steps. The runner temporarily appends the definition to a separate copy of the catalog and uses no steering or arena translation; its preview camera follows the center of mass. `--frames` accepts 1–1800 steps and `--output` changes the recording directory.
